# 数据与安全边界

## 公开内容

本仓库包含运行代码、合成测试、配置占位符和通用文档。公开发行使用新的 Git 历史；不导入个人工作规则、客户端记忆、备份脚本、真实日志、历史运行目录或凭据。

`local/`、环境文件、数据库、密钥和常见客户端状态目录被 Git 忽略。`.gitignore` 不能清除已经提交的内容，也不能识别所有业务秘密。

`scripts/check-public.py` 检查 Git 索引内的文件路径和常见凭据 / 私人路径模式，输出定位信息而不回显匹配值。它是辅助检查，不能替代人工阅读，也不保证发现所有秘密。

## 使用时的数据流

- Replay / demo 不调用模型服务商，也不启动真实 GitHub MCP。
- 真实模型会收到目标、选中的日志 / 源码片段、历史经验和工具返回。项目根约束限制可读取路径，不意味着这些内容不会被发送给模型服务商。
- 启用 GitHub MCP 后，查询请求会发给 GitHub，issue 正文可进入模型上下文。
- 运行目录保存证据、调用轨迹、模型输出和本机路径。将它视作可能包含敏感信息的本地数据；不要直接上传或提交。
- Key 从环境读取，配置保存变量名而非 Key 值。凭据文件读取和有限文本模式脱敏由程序约束；未覆盖的商业秘密仍可能出现在输入、模型响应或本地产物里。

请只分析自己有权提供的材料。需要私密处理时先使用合成 / 脱敏输入，并确认模型服务商的数据政策满足自己的要求。

## 能力边界

没有任意 shell、业务文件写入或 GitHub 写入工具。目录和工具 allowlist 由程序执行。源码、日志、issue 和经验正文仍是不可信输入；提示注入隔离并不完整。该工具也不提供抵抗本机磁盘操作者篡改运行记录的审计保证。

发现敏感信息时不要把原值贴进公开 issue；先通过 GitHub 个人资料中的合适私密渠道联系维护者，或在本机修复后提交只含合成样例的报告。
